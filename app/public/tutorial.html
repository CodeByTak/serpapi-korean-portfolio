SerpApi로 Naver와 Google 검색 결과 비교하기

같은 검색어를 넣어도 Naver와 Google이 보여주는 결과는 꽤 다릅니다. SerpApi로 두 검색 엔진에 요청을 보내는 방법과, 실제로 비교해 보니 어떤 차이가 보였는지 정리했습니다.

준비물

  • JavaScript 기본 문법 (변수, 배열, async/await)
  • 서버에서 JavaScript를 실행할 수 있는 환경 (Node.js 18 이상, 또는 Vercel 같은 serverless 환경)
  • SerpApi API 키 (serpapi.com에서 무료로 발급할 수 있습니다)

코드는 브라우저가 아니라 서버에서 실행합니다. 이유는 바로 아래에서 설명하겠습니다.

API 키 설정하기

API 키는 코드에 직접 적지 말고, 서버의 환경 변수 SERPAPI_KEY에 넣어 두시기 바랍니다.

bash
export SERPAPI_KEY=여기에_내_API_키
🔒 API 키를 브라우저 코드에 넣으면 누구나 개발자 도구에서 볼 수 있습니다. 그래서 검색 요청은 반드시 서버에서 보내야 합니다. 또 요청 URL에 키가 포함되기 때문에, 디버깅할 때도 전체 URL을 로그에 출력하지 않는 것이 안전합니다.

Naver와 Google에 동시에 요청 보내기

SerpApi는 하나의 endpoint(https://serpapi.com/search.json)로 여러 검색 엔진을 다룰 수 있습니다. engine 값만 바꾸면 되는데, 검색어를 담는 파라미터 이름은 엔진마다 다릅니다.

Naver

검색어: query

결과: web_results

Google

검색어: q

결과: organic_results

한국 검색 환경: gl=kr, hl=ko, location=Seoul, South Korea

아래 코드는 두 요청을 동시에 보내고 결과를 받아 오는 핵심 부분입니다.

JavaScript
async function compare(query) {
  const key = process.env.SERPAPI_KEY;

  if (!key) {
    throw new Error('SERPAPI_KEY가 필요합니다.');
  }

  const endpoint = 'https://serpapi.com/search.json';

  const googleParams = new URLSearchParams({
    engine: 'google',
    api_key: key,
    q: query,
    gl: 'kr',
    hl: 'ko',
    location: 'Seoul, South Korea',
  });

  const naverParams = new URLSearchParams({
    engine: 'naver',
    api_key: key,
    query,
  });

  const responses = await Promise.all([
    fetch(`${endpoint}?${googleParams}`),
    fetch(`${endpoint}?${naverParams}`),
  ]);

  if (responses.some((response) => !response.ok)) {
    throw new Error('검색 요청 중 HTTP 오류가 발생했습니다.');
  }

  const [googleData, naverData] = await Promise.all(
    responses.map((response) => response.json())
  );

  if (
    Object.hasOwn(googleData, 'error') ||
    Object.hasOwn(naverData, 'error')
  ) {
    throw new Error('SerpApi가 오류를 반환했습니다.');
  }

  return {
    google: googleData.organic_results,
    naver: naverData.web_results,
  };
}

서버 코드에서는 이렇게 호출하면 됩니다.

JavaScript
const results = await compare('제주도 여행');

여기서 알아 두면 좋은 점이 두 가지 있습니다.

  1. 결과가 담기는 위치가 다릅니다. Google의 일반 검색 결과는 organic_results에, Naver의 웹 검색 결과는 web_results에 들어 있습니다.
  2. HTTP 상태만으로는 부족합니다. 요청이 성공(200)해도 JSON 안에 error 필드가 있을 수 있습니다. 그래서 HTTP 상태와 error 필드를 모두 확인했습니다.

실제 프로젝트 코드에는 timeout 처리도 들어 있고, 각 엔진에서 결과를 최대 5개만 골라 title, link, snippet만 남기도록 정리했습니다. 두 엔진의 응답 구조가 다르기 때문에, 이렇게 같은 형태로 맞춰 줘야 내용을 제대로 비교할 수 있었습니다.

결과 비교: "제주도 여행"

제주도 여행으로 검색한 결과를 저장해 두고 나란히 비교해 보니 세 가지 차이가 눈에 띄었습니다.

1. 첫 번째 결과부터 달랐습니다

Naver 1위
한국관광공사의 섭지코지 여행지 페이지
Google 1위
나무위키의 제주도 페이지

Google은 제주도 자체에 대한 설명으로, Naver는 구체적인 여행지 안내로 시작한 셈입니다.

2. 나온 페이지의 성격이 달랐습니다

Naver
Tripadvisor 관광명소, Expedia 항공권·호텔, 비짓제주
Google
제주도청, 위키백과, 제주도 기자협회

이번 결과만 보면, 여행 계획을 바로 세우기에는 Naver 쪽 결과가 더 유용했습니다.

3. snippet에서 차이가 가장 분명했습니다

Naver · 비짓제주
관광지, 음식점, 숙박, 교통 정보를 제공한다는 설명
Google · 제주도청
"이 페이지에 관한 정보가 없습니다."

제목만 보면 비슷해 보여도 snippet까지 읽으니 어떤 페이지인지 훨씬 쉽게 알 수 있었습니다.

⚠️ 이건 특정 시점에 저장한 한 번의 결과입니다. 검색 결과는 시간, 위치, 설정에 따라 달라지니 다른 검색어에서도 늘 같다고 볼 수는 없습니다. 또 Google에는 지역·언어 설정을 넣었지만 Naver에는 같은 형식의 설정이 없어서, 두 결과가 완전히 같은 조건에서 나온 것도 아닙니다. 이 비교의 목적은 어느 쪽이 더 낫다고 판단하는 게 아니라, 차이를 직접 눈으로 확인하는 것입니다.

English summary

This tutorial shows how to call SerpApi from a server to compare Google and Naver results side by side. Google takes the search term as q and returns results in organic_results; Naver uses query and web_results. The API key stays in the server environment, and the code checks both the HTTP status and the error field. In a saved "제주도 여행" (Jeju trip) search, the two engines differed in their first result, the types of pages returned, and how informative their snippets were. These observations come from one saved result and are not general claims about either engine.
